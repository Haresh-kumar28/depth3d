# DepthWizard v1.5.0 — Final Architecture

## Product workflow
Prepare → Reconstruct → Calibrate → Validate → Explore → Inspect → Compare → Export.

## Accuracy stack
- Native-resolution geospatial metadata and CRS preservation.
- Overlapping tiled Depth Anything V2 inference.
- Configurable 518/768/1024 inference resolution.
- Configurable tile size and overlap.
- Optional edge refinement and terrain smoothing.
- Small/Base/Large Depth Anything V2 engines.
- Explicit Aerial-Depth checkpoint option. No fabricated weights are shipped; a real fine-tuned checkpoint must exist at `models/aerial-depth/`.
- DEM calibration supports a deterministic calibration/holdout split (default 80/20).
- GCP calibration remains available and is recorded independently.
- Validation can use independent holdout pixels from the latest DEM calibration or a separate reference.
- Raster alignment is performed before comparison.
- Validation records reference type (DEM / DSM / LiDAR-derived).
- Reports disclose that 1 m DEM references are generally bare-earth and may not equal a vegetation/building DSM.

## Persistence
Every project keeps `project_state.json` plus a local SQLite index `data/depthwizard.db`.

Tables:
- projects
- reconstruction_runs
- calibration_runs
- validation_runs
- inspection_points
- artifacts

Large artifacts remain as files: GeoTIFF, NPY, PNG, GLB, HTML and JSON. Run records keep parameters, metrics, references and current-run IDs.

## Frontend
The frontend is organized as task-based workspaces:
- Overview
- Project / Imagery
- Reconstruction
- Calibration
- Validation
- 3D Terrain
- Inspection
- Error Analysis
- History
- Exports
- Settings

The project ID is restored from localStorage and the backend reloads state from disk, so refresh/restart does not erase analysis history.
